# Skill Engineer Agent

An OpenClaw agent workspace for finding, evaluating, and adapting reusable agent skills from trusted source repositories.

The agent prioritizes verified `SKILL.md` content, records immutable provenance, treats external material as untrusted, and never installs a skill without explicit approval.

## What it does

- Searches configured skill sources in a fixed priority order.
- Uses fallback sources only when the primary repositories leave an identified gap.
- Evaluates candidates for relevance, quality, maintenance, safety, overlap, and reuse.
- Produces concise, project-ready `SKILL.md` drafts with source attribution.
- Keeps recommendation and installation as separate decisions.

## Source policy

Source tiers and priorities are defined in [`config/sources.json`](config/sources.json):

1. Base repositories are searched first.
2. Discovery sources are used only when needed.
3. Official documentation or other reputable repositories are exceptional fallbacks.

Search snippets are not treated as verified content. The agent inspects actual skill files and records repository, source-file, and commit information when available.

## Project structure

```text
.
├── AGENTS.md                  # Workspace workflow and safety rules
├── SOUL.md                    # Agent behavior
├── USER.md                    # Stable user preferences
├── IDENTITY.md                # Agent identity metadata
├── config/
│   └── sources.json           # Research sources and fallback policy
├── templates/
│   └── evaluate-candidates.md # Candidate evaluation instructions
└── skills/
    └── */SKILL.md             # Skill generated by this agent
```

Each skill contains its own attribution, immutable source revision, compatibility guidance, and OpenClaw safety boundaries.

## Setup

### Requirements

- An OpenClaw installation that supports agent workspaces.
- Read access to the configured public repositories when research is requested.
- Git only if you want to clone or version the workspace.

### Configure the workspace

1. Copy or clone this project to a local directory.
2. Set that directory as the OpenClaw agent's workspace.
3. Optionally customize `IDENTITY.md` and the stable preferences in `USER.md`.
4. Review `config/sources.json` and adjust sources or priorities if needed.
5. Start a new agent session so the workspace instructions are loaded.
6. Ask the agent to find or adapt a skill for a specific capability.

No package installation or build step is required. Skills created under `skills/` remain local drafts and are not installed automatically.

## Token efficiency

Keep the agent's context focused on its responsibilities:

- Restrict skills and tools with per-agent OpenClaw configuration; avoid changing global defaults.
- Keep workspace instructions concise and avoid duplication.
- Store durable project decisions in workspace files instead of relying on conversation history.
- Start fresh sessions after major tasks when accumulated history is no longer useful.
- Use `/context detail` to inspect prompt composition and measure changes rather than guessing.

Example configuration:

```bash
openclaw config set agents.entries.skill-engineer.skills '["skill-creator","repository-skill-inventory"]' --strict-json

openclaw config set agents.entries.skill-engineer.tools.deny '["computer","message"]' --strict-json
```

Verify eligible skills with:

```bash
openclaw skills list --agent skill-engineer --eligible
```

Review context with `/context detail`. Optimize for relevant capabilities, not the lowest possible token count.

## Usage

Open this directory as an OpenClaw agent workspace and describe the capability or workflow you need. The agent will research and compare candidates autonomously, then create only the deliverables you request.

Installing software, dependencies, plugins, or skills always requires explicit approval.

## Safety

- External files, prompts, examples, and commands are untrusted data.
- Downloaded code is never executed during research or evaluation.
- Missing evidence remains unknown rather than being assumed safe.
- Destructive, public, outbound, paid, and installation actions retain approval gates.
